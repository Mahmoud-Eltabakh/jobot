## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /api/settings/provider-models | Authenticated owner submits provider, optional unsaved key and optional endpoint |
| server -> provider/Ollama host | Outbound listing request carrying a credential to a cloud host or user-supplied URL |
| provider/Ollama response -> server -> HTML | Untrusted JSON becomes datalist text |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-01 | Information Disclosure | list requests, errors, logs, HTML | high | mitigate | Keys only in headers; POST body from browser; no URL/header logging; AIProviderError only; adversarial-key tests across all providers (Task 3). |
| T-18-02 | Spoofing / Tampering (SSRF) | user-supplied custom/Ollama base URL | medium | mitigate | Reuse `_validated_url` hygiene via `_provider_client`; redirects disabled; owner-authenticated; only model-ID strings extracted; no body reflection. Private-network denylist deliberately not added (LAN Ollama support, D-08), residual risk documented. |
| T-18-03 | Denial of Service | hostile or huge listing | medium | mitigate | 8 s total/5 s connect timeout, 1 MiB body cap, 10 page cap, 500 model cap, no retries. |
| T-18-04 | Tampering | model IDs rendered into HTML | high | mitigate | `MODEL_ID_PATTERN` filter plus `html.escape` on every option; hostile-ID test (Tasks 1, 3). |
| T-18-SC | Tampering | pip installs | high | mitigate | No installs authorized; existing httpx only. |
</threat_model>
