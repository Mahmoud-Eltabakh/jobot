<objective>
Prove the hosted security model before building any user-facing SaaS workflow. This phase turns the product contract into controlled access rules, ownership validation, and negative tests for tenant leakage.

Output: ownership enforcement checklist, cross-account regression plan, and sensitive-data flow map.
</objective>

## Tasks

<task type="analyze">
  <name>Task 1: Inventory ownership boundaries</name>
  <behavior>
    - audit all user-owned entities: profiles, jobs, notes, tasks, exports, generated materials, settings, vectors, and provider keys
    - identify historical nullable ownership or legacy records that can bypass isolation
  </behavior>
  <action>Produce a data inventory with owner requirement and risk status for each persisted object.</action>
  <done>Every user-scoped table and artifact is mapped to an owner rule.</done>
</task>

<task type="test">
  <name>Task 2: Add cross-account negative tests</name>
  <behavior>
    - at least two users are used in the regression suite
    - each route or service boundary that touches user-owned content is checked for forbidden cross-user access
  </behavior>
  <action>Add regression tests covering read, write, export, and task operations across account boundaries.</action>
  <done>Cross-account leakage is treated as a failure condition in the hosted beta design.</done>
</task>

<task type="design">
  <name>Task 3: Define fail-closed security behavior</name>
  <behavior>
    - missing ownership is treated as a security failure
    - provider calls and storage writes do not proceed when identity is mismatched or ambiguous
  </behavior>
  <action>Document the fail-closed policy for API routes, background workers, and export/deletion requests.</action>
  <done>No hosted read or write path silently falls back to global access.</done>
</task>

<task type="design">
  <name>Task 4: Map sensitive data flow</name>
  <behavior>
    - capture input to provider request to response to storage and export
    - list all places where sensitive data can appear in logs, errors, backups, and vector stores
  </behavior>
  <action>Create a sensitive-data flow map with mitigation steps and residual risk notes.</action>
  <done>All sensitive data flows are explicitly inventoried and reviewed.</done>
</task>

## Success Criteria

Phase 20 is complete when tenant boundaries are proven by negative tests and the security design clearly covers ownership, cross-user leakage, and sensitive-data movement before the hosted runtime foundation is built.
